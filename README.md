# or: cp .env.example .env

Create the PostgreSQL database, then run:
psql "$DATABASE_URL" -f db/schema.sql

Start the API:
npm run dev

Then create the admin account by POSTing to:
http://localhost:4000/api/admin/create

Use the ADMIN_EMAIL and ADMIN_PASSWORD from .env.

## Local database — easiest option

If Docker Desktop is installed:

1. From the project root run:
   `docker compose up -d`
2. In `server/.env`, use:
   `DATABASE_URL=postgresql://postgres:postgres@localhost:5432/all_cleaning_services`
3. Set a strong `JWT_SECRET`.
4. Set `ADMIN_EMAIL` and `ADMIN_PASSWORD`.
5. In `server/`, run `npm install`, then `npm run dev`.
6. Open the frontend with `npm install` and `npm run dev` inside `client/`.

The database schema automatically creates the users, services and bookings tables and seeds the seven cleaning services.

## Current end-to-end flow

Customer registers/logs in → submits booking → booking is stored in PostgreSQL → admin logs in → admin sees booking → admin changes status → customer can see the updated status in the dashboard.

For public launch, production hosting, HTTPS, backups, rate limiting, notifications, and final browser/device testing still need to be configured.


## Production launch package

The project is now prepared for a single-service deployment:

- Express serves the compiled React frontend.
- PostgreSQL remains the application database.
- `render.yaml` provides a Render deployment blueprint for the web service + database.
- `Dockerfile` provides an alternative container deployment.
- `JWT_SECRET` is generated by Render; admin email/password are supplied as deployment secrets.

### Important before going public

1. Create the deployment on your hosting provider.
2. Add your chosen admin email and a strong admin password as private environment variables.
3. Run the database schema (`server/db/schema.sql`) against the production PostgreSQL database if your provider does not execute it automatically.
4. Create the admin account by calling `POST /api/admin/create` once the server is running.
5. Test registration, login, booking, admin status updates, phone/WhatsApp and TikTok links.
6. Connect a production domain and HTTPS.
7. Configure backups and notification delivery before accepting real customer bookings.

The code is ready for these deployment steps, but deployment itself requires access to your hosting account.
